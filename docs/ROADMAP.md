# StudentHub roadmap

This roadmap describes the intended direction of the project. It is a plan, not a promise that every item is already implemented.

## Phase 1 — Foundation

- [x] Create the public repository and enable issue tracking.
- [x] Add a responsive dashboard starter.
- [x] Add a basic task creation and completion interaction.
- [ ] Gather feedback from students about the most useful first workflows.
- [ ] Improve accessibility and add basic browser tests.

## Phase 2 — Core academic organisation

- [ ] Add, edit, and remove courses.
- [ ] Build a timetable that students can customise.
- [ ] Add assignment due dates, status, and priority.
- [ ] Add deadline sorting and overdue indicators.
- [ ] Persist user data locally for the first usable release.

## Phase 3 — Student resources

- [ ] Organise links and files by course.
- [ ] Add course announcements.
- [ ] Add search and filtering across academic items.
- [ ] Improve empty, loading, and error states.

## Phase 4 — Product readiness

- [ ] Evaluate authentication and secure data storage.
- [ ] Design a backend/API architecture if multi-device sync is needed.
- [ ] Add automated tests and continuous integration.
- [ ] Publish setup, deployment, and user documentation.

## Prioritisation

The project should solve common student problems before expanding into complex features. Contributors should propose scope changes through GitHub issues and explain the student need they address.
